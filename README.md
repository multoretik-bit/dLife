# dLife — профиль и расписание

Модульное приложение с профилем и ежедневными блоками. Исходный dhabits не изменён.

## Локальный запуск

Node.js 24+: `npm run dev`, адрес http://127.0.0.1:4173. Локальные данные хранятся в SQLite: `.sites-runtime/local.sqlite`. Для сборки установите зависимости через `npm ci`. Three.js 0.180.0 хранится локально с MIT-лицензией. Проверки: `npm test`.

## Vercel

Репозиторий уже настроен через `vercel.json`: Vercel запускает `npm run build` и публикует `dist/client`. Корневой каталог проекта в настройках Vercel должен оставаться корнем репозитория. Команды Build Command и Output Directory в панели лучше оставить пустыми, чтобы применялись значения из репозитория.

Сборка Vercel полностью статическая и не вызывает Sites Worker. До подключения Supabase приложение работает из браузера и хранит состояние в `localStorage`, поэтому отсутствие серверной функции не приводит к `FUNCTION_INVOCATION_FAILED`.

## Supabase

1. Выполнить `supabase/schema.sql` в SQL Editor выбранного проекта Supabase.
2. В Authentication → Providers включить Anonymous Sign-Ins. Это позволяет войти с личным кодом без email и пароля.
3. Открыть «Синхронизация» на главной странице. Создать код вида `DLIFE-XXXX-XXXX-XXXX` и сохранить его в надёжном месте.
4. На другом устройстве открыть тот же раздел и ввести этот код. Блоки, задачи, привычки, таймер, прогресс, шаги и монеты загрузятся из общего пространства.
5. Для показа капитала dMoney войти ниже по email и паролю. dLife повторно привяжет пространство с кодом к новой Supabase-сессии.

Код хранится в Supabase только в виде SHA-256 хеша. Доступ к данным выдаётся через RPC текущей анонимной или обычной Supabase-сессии; прямой доступ к таблицам закрыт RLS. Запись выполняется с проверкой ревизии, а предыдущие состояния сохраняются в резервной таблице. На главной странице также доступна выгрузка JSON. Secret/service-role ключи в браузер вводить нельзя и приложение их отклоняет.

## Страницы

- `/` — профиль с навигацией.
- `/now/` — текущий блок и редактор расписания.
- `/embed/now/` — текущий блок для встраивания; `?id=UUID` — конкретный блок.
- `/blocks/profile/` — постоянная ссылка на блок.
- `/embed/profile/` — блок без навигации и внешнего фона для iframe/Notion.

Ссылка копируется через значок ссылки в шапке. В Notion используется команда `/embed`. Не является нативным редактируемым блоком Notion. Для отображения необходим доступный HTTPS-адрес; приватная авторизация и ограничения хостинга на iframe могут препятствовать встраиванию. Доступ сайта намеренно не расширяется автоматически.

## Время

Дата рождения 14.09.2004. День рождения считается первым днём жизни. Счёт календарный, включая високосные дни. Часовой пояс явно задан в `dist/life.js`: Asia/Krasnoyarsk. Обновление раз в 15 секунд и при возврате на вкладку. Утро 05–12, день 12–18, вечер 18–23, ночь 23–05.

## Персонаж

Оригинальный `profile-avatar.png` из dhabits, без изменения файла. Настоящий 2D skeletal mesh в Three.js: torso → neck → head, две кости плеч и две кости век. Сетка 100×120, до четырёх нормализованных весов на вершину. Это 2D-риг рисунка, не объёмная 3D-модель. Взгляд из исходного портрета направлен на зрителя; лёгкий поворот головы, дыхание и локальные движения век создаются костями, а не CSS-качанием всего изображения.

Анимация учитывает prefers-reduced-motion, останавливается вне видимой области и на скрытой вкладке, имеет ручную паузу. При отсутствии WebGL сохраняется статический портрет. Цвета/одежда прежнего состояния магазина не импортируются.

## Брендинг

Использован предоставленный пользователем PNG логотипа dLife как favicon и знак в шапке. Интеграция с Notion API не подключена; предусмотрены самостоятельные страницы для iframe.

## Расписание и хранение

Шестерёнка открывает создание, изменение и удаление блоков, привычек и задач. Блоки повторяются ежедневно и выбираются по локальному времени устройства. Начало включительно, окончание исключительно; переход через полночь поддерживается. Пересечения запрещены. Вне расписания показан розовый отдых. Привычки отмечаются заново каждый день (ночные относятся к дате начала блока); задачи сохраняют выполнение. Цвета ограничены десятью сферами из пользовательского образца. Иллюстрация выбирается по сфере блока.

В старом Sites-развёртывании данные хранятся в D1, изолированы по доверенному заголовку авторизации Sites. В Vercel-развёртывании используется Supabase после его настройки либо локальное хранилище браузера до подключения. API и Supabase RPC используют проверку ревизии, чтобы параллельные изменения не затирали друг друга. Локальная разработка на порту 4173 использует отдельную SQLite и фиксированного локального пользователя; данные тестирования не переносятся на хостинг автоматически.

`npm test` — календарь, расписание, валидация, API, изоляция и конфликты. `npm run build` — клиент, Worker и миграции. Авторские клиентские файлы лежат в корне `dist/`; `dist/client`, `dist/server`, `dist/.openai` генерируются сборкой. Миграции создаются `npm run db:generate`.

## Визуальная система

Светлая оболочка с голубыми рабочими панелями, крупной типографикой и абстрактной графикой. Тема `dist/design.css` применяется ко всем маршрутам. `/aspects/` показывает четыре аспекта и сумму длительностей ежедневных блоков по десяти сферам; это запланированное время, не рекомендуемая норма. `/embed/aspects/` и `/blocks/aspects/` — самостоятельные представления. Страница дня содержит временную шкалу и быстрый вход в редактор.

## Привычки, календарь и развитие

Раздел «Задачи» имеет режимы «Сейчас», «Сегодня», «Месяц». `blockId: ""` обозначает задачу/привычку на весь день. Датированные задачи появляются в календаре; weekly повторяет день недели начиная с первой даты. Выполнение датированных задач хранится отдельно для каждого вхождения. Задачи без даты сохраняют старое поведение: одна постоянная отметка. Привычки используют ежедневные отметки; текущая серия считается до 21, пропуск полного календарного дня обнуляет её, история остаётся. Ночные привычки в текущем блоке относятся к дате начала блока.

Время и нормы: practices — именованные занятия с дневной нормой, logs — записи минут, spherePlans — видение/срок/инструменты/результаты для сферы, timer — сохранённое начало отсчёта. Таймер продолжает работать при закрытии страницы. При завершении выбираются сфера и занятие; длительность можно уточнить. Запись относится к выбранной дате (по умолчанию день завершения), автоматически не делится на две даты. Ручная запись времени доступна отдельно. Прогресс каждого занятия считается по его id и дате, а не суммой всей сферы. Старые данные загружаются без миграции и без сброса.

`/sphere/?id=10` — пример страницы сферы. `/embed/sphere/?id=10&section=vision` (или tools, results) показывает только выбранный модуль. Кнопки «Ссылка» дают адрес каждой секции. На хостинге для сохранения данных по-прежнему требуется авторизованный пользователь; настройки аудитории не меняются.
